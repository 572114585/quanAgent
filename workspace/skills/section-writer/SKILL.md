# Section Writer 逐节撰写方法论

本 skill 是**撰写方法论参考文档**，section-writer 子 agent 在撰写单节内容时读取本文件了解撰写规范。

## A. 撰写单节流程

```
1. 解析 description 中的信息（大纲/当前节/素材路径/全局约定）
2. read_file 检索素材，提取当前节所需信息
3. 按呈现方式撰写 md 内容（含占位符）
4. write_file 写入 /tmp/sections/<section_n>.md
5. 返回摘要 + 文件路径
```

## B. 呈现方式占位符格式

占位符在 md 中**独占一行**，后续 HTML 制作阶段会替换为实际的可视化组件。

| 占位符 | 含义 | 示例 |
|---|---|---|
| `{{chart:类型-描述}}` | 图表占位 | `{{chart:柱状图-2021-2025年市场规模}}` |
| `{{table:描述}}` | 表格占位 | `{{table:主流框架功能对比}}` |
| `{{flowchart:描述}}` | 流程图占位 | `{{flowchart:Agent感知-规划-执行-学习循环}}` |
| `{{concept-map:描述}}` | 概念图占位 | `{{concept-map:AI Agent技术架构层级}}` |
| `{{timeline:描述}}` | 时间线占位 | `{{timeline:AI Agent发展历程2019-2026}}` |
| `{{comparison-matrix:描述}}` | 对比矩阵占位 | `{{comparison-matrix:LangChain vs AutoGPT vs CrewAI}}` |
| `{{data-card:描述}}` | 数据卡片占位 | `{{data-card:全球AI Agent市场规模$50亿}}` |
| `{{quote:内容}}` | 引用块占位 | `{{quote:AI Agent是下一个重大技术范式转变}}` |

### 占位符使用原则

1. **独占一行**：占位符前后空行，不与其他文字混排
2. **描述清晰**：描述部分要足够具体，让后续 HTML 制作者知道要画什么
3. **类型准确**：选择最匹配的占位符类型（数据趋势→chart，过程→flowchart，层级→concept-map）
4. **适度使用**：不是每段都要占位符，文字论述段落不需要

### md 内容示例

```markdown
## 2. 技术原理

AI Agent 的核心技术架构基于"感知-规划-执行-学习"循环 [2]。感知层负责接收环境信息，规划层进行任务分解和决策，执行层调用工具完成任务，学习层根据反馈优化后续行为 [4]。

{{flowchart:Agent感知-规划-执行-学习循环}}

在感知层，主流方案是多模态输入融合...

{{concept-map:AI Agent技术架构层级（感知层/规划层/执行层/学习层）}}

关键技术组件包括：记忆系统（短期+长期）、工具调用框架、推理引擎等 [5]。
```

## C. 引用标注规则

```
- 引用来源用 [编号] 标注，编号对应 /tmp/research/*.md 中的来源编号
- 示例：AI Agent 市场规模预计 2026 年达到 500 亿美元 [3]
- 多个来源用 [3][5] 标注
- 每节末尾不需要列 Sources（全文统一在最后列）
- 引用应紧跟在被引用的数据或观点之后
```

## D. 全局连贯性要求

撰写时参考完整大纲，确保：

1. **不重复**：不重复其他节已覆盖的内容（如"概述"已定义的概念，"技术原理"不重复定义）
2. **术语统一**：术语使用全局约定中的统一术语
3. **引用一致**：引用编号与其他节一致（同一来源用相同编号）
4. **逻辑关联**：本节内容与前后节有逻辑关联（如"上一节介绍了原理，本节将对比主流框架"）
5. **承上启下**：节首可简要承接前文，节末可引出后文

## E. 内容质量要求

1. **有据可查**：内容必须有来源支撑，不编造数据
2. **诚实标注**：缺数据用 `[此处需要补充: xxx]` 占位
3. **字数灵活**：预计字数是大致参考，内容质量优先于字数
4. **数据标注**：数据要标注年份和来源
5. **区分性质**：区分事实、推断和预测（预测需标注"预测"字样）
